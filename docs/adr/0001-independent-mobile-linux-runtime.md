# Independent Mobile Linux Runtime Delivery

The Linux environment is delivered as **our own experimental, internal** Cordis bootstrap and runtime plugins, independently versioned from the app, with Bionilux, a Debian minimal rootfs, and one shared app-level glibc Node.js package distributed as checksummed GitHub Release assets rather than Git/LFS content. The bootstrap is distributed with the app in the built-in (hard) plugin directory; the runtime plugin comes from a Release. Neither is **enabled by default**: presence is not activation, and neither an APK update nor a Linux release enables them. Because the bootstrap requires function-valued configuration, it is loaded by the host only when the user explicitly enables the system rather than mounted from a profile. This keeps DSH Mobile’s Bionic Node and Termux execution path unchanged, avoids duplicating Node into each rootfs, and lets system updates remain independent of app releases; automatic update checks are triggered only for an explicitly activated system when the installed DSH Mobile app version changes, while manual checks remain available. The Debian rootfs is an execution environment, not a security boundary.
